==================================================

WhyLab should answer:

"What is wrong with my ML system, what evidence supports that conclusion,
how can we test whether that explanation is correct, what should I change,
and did the change actually improve the system?"

The fundamental workflow should be:

INPUT
  ↓
VALIDATION
  ↓
DATA / MODEL EVIDENCE
  ↓
AI-GUIDED INVESTIGATION
  ↓
HYPOTHESES
  ↓
DETERMINISTIC TESTS
  ↓
FALSIFICATION / VERIFICATION
  ↓
DIAGNOSIS
  ↓
REPAIR OPTIONS
  ↓
APPLY / SIMULATE REPAIR
  ↓
RE-EVALUATE
  ↓
BEFORE-vs-AFTER EVIDENCE
  ↓
INCIDENT / RELIABILITY REPORT
  ↓
MONITORING RECOMMENDATIONS

Never collapse this into:

metrics → LLM → paragraph.

==================================================
CRITICAL AI ARCHITECTURE RULE
==================================================

GPT-6 Astra must function as the INVESTIGATION ORCHESTRATOR.

Astra should decide, when appropriate:

- what evidence is missing
- which deterministic diagnostic tool should run
- which hypotheses are plausible
- which hypotheses deserve priority
- what evidence supports or weakens them
- which experiment could falsify them
- what repair candidate should be evaluated
- what success criterion should be used
- whether enough evidence exists to make a conclusion

However:

ASTRA MUST NOT INVENT NUMERICAL RESULTS.

All statistics, metrics, thresholds, scores, counts, tests, distributions,
confusion matrices, calibration values, drift values, and before/after
measurements must come from deterministic application code.

The AI reasons over evidence.

The deterministic engine computes evidence.

Maintain this boundary throughout the architecture.
