## 1. Executive Assessment & Audit Scope

WhyLab 2.0 is currently a hardened, production-ready SaaS platform with **185 passing automated tests**, **0 TypeScript compilation errors**, and a **clean Next.js App Router build (41 routes)**. Its existing architecture provides deterministic mathematical evaluations, multi-tenant RBAC, cryptographic object storage, asynchronous worker queues, reconnectable SSE telemetry streams, an evidence falsification DAG, and a decision policy Repair Lab.

However, the existing diagnostic engine, dataset schema contracts, and UI dropzones are **strongly coupled to tabular classification records** (specifically binary classification with `actual`, `predicted`, `probability`, and tabular feature columns).

To fulfill the mentor directive of **prioritizing LLM and Computer Vision reliability**, WhyLab 2.0 must be extended into a **multi-modal failure investigation platform** comprising three distinct, first-class investigation modes:
1. **Tabular ML Investigation** (Preserve 100% of existing functionality, golden fixtures, and test guarantees).
2. **LLM & RAG Reliability Investigation** (Implement first: prompt-response evaluations, deterministic NLP metrics, JSON schema compliance, RAG retrieval recall/MRR, context attribution, and prompt repair).
3. **Computer Vision Investigation** (Implement second: safe image archive ingestion, classification metrics, image quality diagnostics, perceptual duplicate leakage, shortcut learning detection, and quality filtering repairs).

## 2. Architectural Principle: Modality-Specific Adapters over Forced Monoliths

A critical architectural pitfall in ML observability platforms is attempting to force heterogeneous modalities into a generic tabular table (e.g. storing raw 5MB image byte strings or nested RAG citation graphs into standard CSV columns).

WhyLab 2.0 will strictly adhere to:
- **Modality-Specific Contracts:** Typed schemas for Dataset Modality, Prediction Records, Diagnostic Tool Inputs/Outputs, and Repair Policies.
- **Shared Investigation Substrate:** Universal reuse of the Astra multi-turn orchestrator, Evidence DAG, Hypothesis Falsification engine, Monotonic Telemetry Event Hub, Human Gatekeeper Approval workflow, and Certified PDF/Markdown Export.
- **Honest Capability Awareness:** No hallucinated metrics or fabricated LLM explanations. Every finding must be grounded in an immutable Evidence ID generated by a deterministic tool.

## 4. Deep-Dive Gap Analysis by Subsystem

### 4.1 Subsystem A: LLM & RAG Reliability Engine

#### Existing Reusable Capabilities
- **Token Usage / Latency Parsing:** `src/core/diagnostics/training-logs.ts` demonstrates parsing regex logs; similar patterns can parse LLM token usage and latency records.
- **Slice Disparities:** `src/core/diagnostics/slice-evaluation.ts` can partition LLM cases by `metadata.model_version`, prompt category, or latency buckets to compute subgroup F1 gaps with 95% Wilson confidence intervals.
- **Audit & Governance:** `src/server/audit/audit-logger.ts` and `src/server/repair/repair-registry.ts` enforce human-in-the-loop review before any prompt modification can be exported.

#### Missing Functionality Required (To be built in L1 & L2)
1. **Schema & Record Representation (`src/core/domain/llm-types.ts`):**
   - Record contract: `case_id`, `prompt`, `response`, optional `reference_answer`, `model_version`, optional `retrieved_context` (array of chunks or `{ id, text, metadata }`), optional `latency_ms`, optional `token_usage` (`prompt_tokens`, `completion_tokens`, `total_tokens`), optional `metadata`.
   - File formats: JSONL (`.jsonl`), structured CSV (`.csv`), or JSON array.
2. **Deterministic Evaluation Metrics (`src/core/diagnostics/llm/`):**
   - **Exact Match (EM):** Case-sensitive string equality against `reference_answer`.
   - **Normalized Exact Match (NEM):** Whitespace-collapsed, punctuation-stripped, lowercased equality.
   - **Token F1 Score:** Tokenized unigram overlap (harmonic mean of token precision and token recall).
   - **JSON Parse Validity Rate:** Percentage of responses that parse cleanly as valid JSON.
   - **JSON Schema Compliance Rate:** Validates responses against user-supplied JSON schema (using zero-dependency pure TypeScript schema validator).
   - **Cost & Latency Summaries:** Mean, median, p95, p99 latency; total tokens, prompt/completion split; estimated USD cost with explicit user-supplied cost parameters (e.g. $2.50 / 1M prompt tokens).
3. **RAG & Retrieval Diagnostics (Milestone L2):**
   - **Recall@k:** Fraction of ground-truth relevant document IDs present in top-k retrieved contexts.
   - **Mean Reciprocal Rank (MRR):** Reciprocal rank of the first relevant document in retrieved contexts.
   - **Hit Rate@k:** Proportion of cases where at least one relevant chunk is retrieved in top-k.
   - **Unsupported-Claim / Attribution Detection:** Deterministic sentence-level n-gram overlap and citation validation against retrieved context chunks.
   - **Rubric-Based Structured Judge:** Optional LLM-as-judge using strictly typed schemas with confidence scores and mandatory "Uncertain / Human Review" status.
4. **LLM Repair Lab Adapter:**
   - Paired prompt comparison: comparing Baseline Prompt (v1) vs Candidate Prompt (v2) on identical evaluation cases.
   - Guardrail repair: recommending schema retry prompts, system prompt instruction constraints, or retrieval k adjustments.

### 4.2 Subsystem B: Computer Vision Diagnostic Engine

#### Existing Reusable Capabilities
- **Classification Metric Mathematics:** `src/core/diagnostics/classification-metrics.ts` provides exact confusion matrix math, accuracy, precision, recall, and F1. Can be extended to multi-class vision problems.
- **Cross-Split Leakage Concept:** `src/core/diagnostics/split-contamination.ts` implements hashing and contamination detection; can be repurposed for image perceptual hash (dHash) comparison.
- **Distribution Shift Tests:** `src/core/diagnostics/drift-tests.ts` provides Kolmogorov-Smirnov and PSI statistics; directly reusable to detect acquisition shift across image sharpness or luminance distributions.
- **Golden Fixtures Already Seeded:** `public/fixtures/vision/` already contains:
  - `synthetic-fixture.json` (131 KB with 200 image profiles: width, height, luminance, contrast, sharpness, dHash, aHash).
  - `predictions.csv` (201 rows with `image_id`, `y_true`, `y_pred`, `y_probability`, `split`, `site`, `device`, `has_ruler`).
  - `README.md` documenting planted defects: scale ruler shortcut (78% vs 5%), near-duplicate leakage (+36.2 pp gap), and camera acquisition shift (site A vs site B).

#### Missing Functionality Required (To be built in C1 & C2)
1. **Safe Archive Ingestion & Sanitization (`src/server/vision/archive-extractor.ts`):**
   - Security protection against decompression bombs (zip bomb attack): maximum uncompressed size 250MB, max 5,000 files, compression ratio ceiling 10:1.
   - Path traversal protection: rejecting any entry containing `..` or absolute paths.
   - Magic byte validation: verifying JPEG (`0xFF 0xD8 0xFF`), PNG (`0x89 0x50 0x4E 0x47`), WebP (`RIFF....WEBP`).
2. **Image Quality & Feature Analysis (`src/core/diagnostics/vision/`):**
   - Dimension validation: width, height, aspect ratio.
   - Luminance / Brightness: mean and standard deviation of pixel intensity.
   - RMS Contrast: root-mean-square contrast across pixel values.
   - Blur & Sharpness Estimation: discrete Laplacian variance / gradient magnitude estimator.
   - Clipping: highlight saturation and shadow crush percentages.
3. **Perceptual Hashing & Leakage Detection:**
   - Pure TypeScript Difference Hash (dHash) and Average Hash (aHash) algorithms operating on grayscale 8x8 / 9x8 pixel grids.
   - Cross-split near-duplicate scanner: computing Hamming distance $\le 1$ bit between training and validation images to detect data leakage.
4. **Shortcut Learning & Confounder Detection:**
   - Correlation analysis between metadata flags (e.g. `has_ruler`, watermark presence) and positive class predictions.
   - Computing performance collapse when the shortcut feature is absent.
5. **Safe Gallery UI & Memory Management:**
   - Generating lightweight WebP/JPEG thumbnails (128x128) during ingestion.
   - Virtualized image grid with pagination and misclassification filters (False Positives, False Negatives).
   - Never decoding all full-resolution images simultaneously in browser DOM.

## 5. Technical Risks, Dependencies & Mitigation Strategy

| Risk ID | Risk Description | Severity | Mitigation Strategy |
| :---: | :--- | :---: | :--- |
| **R-01** | **Regression in Tabular ML Suite:** Modifying shared domain types breaks existing 185 tests. | **Critical** | Keep existing tabular types (`EvaluationDataset`, `DatasetMetadata`) intact. Use discriminated unions (`DatasetPayload = TabularDataset \| LlmDataset \| VisionDataset`). Run `npm test` after every change. |
| **R-02** | **Image Archive Decompression Exploits:** Malicious ZIP files cause denial of service or directory escape (CWE-409, CWE-22). | **Critical** | Enforce strict archive extractor guards: streaming entry count cap, 250MB extracted size limit, and path traversal normalization before disk write. |
| **R-03** | **Heavy Native Binary Dependencies:** Libraries like Sharp, Canvas, or Puppeteer fail in cloud environments or Windows CI. | **High** | Implement image quality and perceptual hash calculations in pure TypeScript Buffer/ArrayBuffer operations, or use standard web APIs (`OffscreenCanvas` / native Node buffers). Zero native C++ node-gyp bindings. |
| **R-04** | **Browser Memory Exhaustion on Vision:** Rendering thousands of uncompressed images crashes the client tab. | **High** | Generate 128x128 thumbnails during ingestion. Use virtualized list / paginated grid with max 50 images per page. |
| **R-05** | **LLM Metric Hallucination:** Relying on unverified model opinions instead of deterministic calculations. | **High** | All core LLM metrics (Exact Match, Token F1, JSON Schema, MRR) are computed in 100% deterministic TypeScript. Any LLM-as-judge score is explicitly labeled as subjective with confidence and human review flags. |
