Primary goal: transform WhyLab from an interactive ML reliability dashboard with planned GPT integration into an Astra-native ML failure investigator that gathers evidence, tests hypotheses, recommends repairs, and verifies whether the repair worked.

Basis: current WhyLab faculty mentorship briefing + current Product Hunt GPT-6 Astra Challenge information + OpenAI GPT-6 Astra model guidance.

How to Use This Document

Students should treat the P0 section as mandatory. Do not start optional features until all P0 items work end-to-end.

Build one flawless flagship investigation before expanding to additional case studies.

Astra must perform meaningful diagnostic planning and tool orchestration; it should not be used only to rewrite deterministic analysis into prose.

Every numerical impact claim shown in the demo must be measured or clearly labelled as simulated under a stated cost model.

1. Challenge Context and Strategic Fit

Current challenge facts. Product Hunt lists the GPT-6 Astra Challenge for September 18, 2026. The challenge asks builders to create something ambitious with GPT-6 Astra, and lists five winners receiving a year of ChatGPT Pro, $10K in API credits, and promotion by OpenAI. Product Hunt also states that participants should schedule their launch for September 18.

Why WhyLab fits. WhyLab already addresses a serious engineering problem: machine-learning systems can report strong offline metrics yet fail in deployment because of class imbalance, distribution shift, target leakage, or cost-insensitive decision thresholds. The current system already follows a strong six-stage workflow: ingest, inspect evidence, rank root causes, run counterfactual verification, repair, and produce production remedies.

Why Astra fits. OpenAI describes GPT-6 Astra as its model for difficult end-to-end, multistep work, with capabilities including async tool calling, mid-turn steering, Structured Outputs, function/programmatic tool calling, multi-agent orchestration, prompt caching and persisted reasoning. These capabilities align naturally with an investigation workflow rather than a simple chat interface.

Do not lead with: "an educational platform that explains ML failures."

Lead with: "WhyLab - an AI incident investigator for machine-learning systems."

Recommended value proposition: Upload your evaluation data. WhyLab investigates why your model is failing, proves the root cause with experiments, and shows you how to repair it.

ML engineers

3. Make Astra the Investigator, Not the Narrator

Avoid this architecture:

CSV / logs    |Deterministic Python analysis    |Final metrics    |GPT-6 Astra    |Natural-language explanation

Target architecture:

User input: CSV / logs / metrics / model artifacts                    |            GPT-6 Astra Investigator                    |     +--------------+--------------+     |              |              | Data Profiler  Leakage Scan   Drift Analyzer     |              |              |     +--------------+--------------+                    |            Evidence collection                    |           Hypothesis ranking                    |        Counterfactual experiments                    |              Repair planner                    |          Verification / re-test                    |       Production-ready fix report

Astra should be responsible for deciding:

Which evidence is missing before it can make a diagnosis.

Which diagnostic tools/tests should be called next.

Which root-cause hypotheses are plausible and how they should be ranked.

What experiment could falsify each important hypothesis.

How to interpret returned measurements without overstating confidence.

Which repair should be tested and what success criterion should be used.

4. P0 Feature: Autonomous Investigation

Add one prominent action in the product:

INVESTIGATE WITH ASTRA

Typical accepted inputs:

predictions.csv

dataset/evaluation CSV

training.log or exported training metrics

optional metadata such as timestamp, environment, group, site, or device

The investigation view should display progress as evidence, not hidden chain-of-thought. Example:

INVESTIGATION #WH-1042[done] Dataset profile complete[done] Class prevalence analyzed[done] Metric contradiction detected[done] Leakage scan completed[done] Distribution-shift tests completed[done] Threshold sensitivity testedPrimary hypothesis: Severe class imbalanceConfidence: 94%Evidence:- Positive prevalence: 5.8%- Accuracy: 94.2%- Balanced accuracy: 51.7%- Minority recall: 22.4%Verification experiment: stratified evaluationResult: hypothesis supported

Important UX rule. Show the evidence, executed tools, measurements, hypotheses and outcomes. Do not expose or simulate private chain-of-thought.

6. Falsification Engine: WhyLab Should Try to Prove Itself Wrong

This is the strongest technical differentiator. WhyLab should not stop at "I think class imbalance is the cause." It should generate a testable hypothesis and run a relevant experiment.

Step

Example

Hypothesis

Class imbalance is causing misleading top-line accuracy.

Prediction

Balanced metrics and minority recall will reveal substantially worse performance than raw accuracy.

Experiment

Run balanced metrics and controlled stratified/resampled evaluation.

Observed result

Measured behavior is consistent with the prediction.

Decision

Support, weaken, or reject the hypothesis.

Next action

Run repair candidate and re-evaluate with the same acceptance criteria.

Recommended product message: "WhyLab does not just guess why your model failed. It runs experiments that can disprove the diagnosis."

9. Make the Repair Lab the Demo Climax

The current WhyLab repair workbench is already visually strong. Upgrade it so Astra can translate a real-world objective into an operating-point recommendation.

User: "Missing a cancer case is 50x worse than sending a patient for an unnecessary test."Current threshold:       0.50Recommended threshold:   0.19Expected effect from current evaluation data:Recall                   22% -> 84%False negatives           776 -> 148False positives           +1,042Reason: the stated FN:FP cost ratio changes the preferred operating point.

Recommended interaction:

User states domain-specific error costs or business/clinical priorities.

Astra chooses an appropriate deterministic threshold/cost optimization tool.

WhyLab calculates candidate operating points.

Astra explains the trade-off using measured values.

User clicks Apply Astra Recommendation.

Confusion matrix, cost, recall, precision and reliability indicators update live.

10. High-Value Differentiator: Challenge WhyLab

After the primary diagnosis, provide an adversarial review mode that tries to find a better explanation or disprove the selected cause.

ADVERSARIAL REVIEWAlternative causes evaluated:Class imbalance       insufficient evidenceCovariate shift       weak evidenceOverfitting            inconsistent with logsTarget leakage         survives challengeDiagnosis confidence: 82% -> 96%

This feature reinforces the reliability / AI-safety positioning because the system actively searches for alternative explanations rather than treating its first answer as final.

12. Reliability Score: A Simple Shareable Outcome

Add an interpretable top-level score only if every component is traceable to actual measurements. Avoid presenting an arbitrary model-generated score.

WHYLAB RELIABILITY SCORE38 / 100   HIGH RISKPerformance quality      82Minority-class safety    31Calibration              44Drift resilience         27Leakage risk             91Cost alignment           18After repair: 38 -> 81

Implementation requirement. Document the score formula and weights. Each sub-score must link back to its evidence. If the team cannot justify the aggregation before launch, show a risk profile instead of a single number.

14. Flagship Case Study and Credibility Rules

Keep all existing case studies in the product, but lead the launch video with one flagship investigation. The melanoma accuracy-paradox case is the clearest because the failure can be understood immediately.

MODEL ACCURACY: 94.2%Looks excellent.WHYLAB INVESTIGATIONMalignant recall: 22.4%The model misses most malignant cases.WhyLab tests:1. Class imbalance2. Threshold misalignment3. Domain shiftRepair and re-test -> show measured before/after result

Credibility rule: if dollar savings, lives affected, legal liability, ARR preserved or other impact values come from a hypothetical cost model, label them clearly as "Simulated impact under the supplied cost model." Never present simulated impact as a measured real-world outcome.

21. Submission Readiness Gate

Do not submit until all mandatory conditions below are true:

[ ] The live product uses GPT-6 Astra, not a mock response.

[ ] Astra calls at least one real diagnostic tool as part of the investigation.

[ ] The user can upload or select real evaluation data.

[ ] The system produces evidence-backed hypotheses rather than unsupported prose.

[ ] At least one hypothesis is verified through a reproducible experiment.

[ ] The Repair Lab demonstrates a measurable before-vs-after change.

[ ] The demo can be repeated reliably from a clean browser session.

[ ] Every displayed metric has correct units and a clear definition.

[ ] Simulated impact is clearly labelled.

[ ] The Product Hunt page, thumbnail, tagline and video all tell the same product story.

[ ] Launch is scheduled for September 18, 2026 according to the current Product Hunt challenge guidance.

22. Final Recommendation

Submit WhyLab, but submit the Astra-native version. The product already has a strong diagnostic foundation. The highest-leverage change is to make GPT-6 Astra an active investigator that orchestrates evidence collection, selects tests, challenges hypotheses, recommends repairs and verifies outcomes.

Target product story: "An autonomous ML failure investigator powered by GPT-6 Astra that gathers evidence, forms hypotheses, runs falsification experiments, repairs the model operating policy, and proves whether the repair worked."

The team should resist feature expansion until the complete investigation loop is stable. One rigorous end-to-end investigation will be more convincing than many partially integrated features.
